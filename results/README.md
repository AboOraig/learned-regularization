# `results/`: what is where

Everything here is generated by the scripts in the repository root (see the README for the commands and [REPORT.md](../REPORT.md) for the experiment cards).
Nothing was renamed or moved after generation, so file names carry the history of the project; this page is the map.
`results/control/` holds the controls added during the paper review. `paper/figures/` holds copies of the figures used in the paper (`bash paper/sync_figures.sh` compares them with this folder).

## Naming conventions

| Pattern | Meaning |
|---|---|
| `m03`, `m05`, `f03` | Denoiser family: MNIST trained with σ_max 0.3 / MNIST 0.5 / Fashion-MNIST 0.3 |
| `_s0`, `_s1`, `_s2` | Independent training seed of the denoiser |
| `_fine5c`, `_fine5`, `_fine5n` | Crime-free data from a 5× finer grid: bicubic (`c`, the one used in the paper), bilinear (`_fine5`), nearest (`n`). No suffix: inverse-crime data |
| `_per_image`, `_images`, `*_metrics.csv` | Raw per-image results; the other CSVs are summaries of them |
| `K30`, `K60`, `K120`; `dose1`, `dose0.25`, `dose0.1` | CT: number of angles (of 1000) and dose (fraction of 4096 photons per ray) |
| `s4c`, `s5` | Stage 3 final runs of the lesion study (`s4c`, 20 validation slices, extended grids) and of the full dose × angle grid (`s5`) |
| `.npz` | Stored per-patient arrays behind the Stage 3 tables (input to the summary scripts) |

## Large files

The per-image `nullspace_metrics*.csv` (about 10 MB each, nine in total counting `step4/`) and the `.npz` arrays in `stage3/` dominate the folder size (about 90 MB). They are the raw data behind the tables and are kept for reproducibility.
